Texts

Section titled “Texts”

In Amber and Red, the braces show a list. The card shows only the items that apply, with ” · ” between them.

Normal (no badge; its tooltip)Checked by Viewpoint. This addon’s Java code uses only parts of Java, the game and Viewpoint that Viewpoint has reviewed. Viewpoint found no way for it to reach your files outside its own folder, the internet, other programs or native code. It can still change anything in your game and saves. In multiplayer, what it puts into the game is sent to the server. The mod’s Lua scripts are not checked. Its assets are checked for their form and size, not for what they do.

The export line

Section titled “The export line”

The words after “they use:” or “it uses:” are the items that the exported functions reach. These are all the items:

threads · the server · Lua · files · the network · programs · native code · classes · reflection · the game’s process · memory · OpenGL · internals of Viewpoint · hooks · parts of the game · other addons

If the functions reach none of them, the line says “nothing that Viewpoint lists”.

The line counts the functions that the exports call. It does not count code that runs when a class loads, or an object that the addon stored for later.

The Lua line

Section titled “The Lua line”

Has Lua: not checked by Viewpoint, then Found in it: and the names that Viewpoint found in the Lua of the mod, for example getModFileWriter, getHostByName or Clipboard. Or No Lua.

Viewpoint lists these names. Some write, read or list files: getFileWriter, getModFileWriter, getFileReader, getModFileReader, getFileInput, getFileOutput, getGameFilesInput, getGameFilesTextInput, listFilesInModDirectory, listFilesInZomboidLuaDirectory, serverFileExists and cacheFileExists. Some reach the internet or the desktop: getHostByName, openUrl, activateSteamOverlayToWebPage, showFolderInDesktop and Clipboard. Some load a file as code or make code, or a global, from text or bytes, which hides it from this check: loadstring, bytecodeloader, reloadLuaFile, reloadServerLuaFile, rawset, setfenv and getfenv. Viewpoint reads the Lua as text. It does not run it, and it cannot see a name that the Lua makes from other text.
