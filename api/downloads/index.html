Downloads

Open Markdown

Use AddonDownloads to get a file from the internet. Do not open network connections yourself: java.net makes the label Red. Viewpoint asks the player each time, and shows the full address.

Permission: downloads, with the hosts in downloads.hosts. The file goes into your AddonFiles folder, so you also need the files permission.

Ask for a download

Section titled “Ask for a download”

A test compiles this code against the API and runs it in an addon.

  • Use an https URL with a host name: no user name, no port, no address of numbers, no hidden character. Viewpoint refuses the others with an IllegalArgumentException at the call.
  • Use a host that is in downloads.hosts. If the server redirects to a different host, put that host in the list also. Viewpoint follows at most three redirects, and judges each one as it judges the first address.
  • Give the file a name with the same rules as AddonFiles.
  • Set declaredBytes to the size of the file. The player sees it.

request(DownloadRequest) gives a Pending<DownloadResult>. Its callbacks run on the main thread. A refusal is not an error. It is a result with a status.

DownloadResult memberMeaning
status()One of the values below.
name()The name of the file in your folder.
bytes()The size that Viewpoint wrote.
finalHost()The host that sent the file, after the redirects. Empty if no host answered.
reason()Why the download did not end in OK, in one sentence. Empty for OK.
status()Meaning
OKThe file is in your folder.
DENIEDThe player did not accept the download.
DENIED_SESSIONThe player did not accept too many times. The addon cannot ask again in this session.
NOT_SHOWNViewpoint could not show the prompt.
TOO_LARGEThe file is larger than the limit.
FAILEDThe download did not complete.

What the player sees

Section titled “What the player sees”

Each call shows a dialog. The dialog shows:

  • the name and the label of the addon;
  • the full URL, with emphasis on the host;
  • the destination: viewpoint-addons/<id>/<name>;
  • the size, if you set declaredBytes.

The player clicks Deny or Accept. Esc is a Deny. Deny works at once. Accept is grey for the first half second after the player first sees the question, and takes a click only after the pointer has rested on it for a moment. If several addons ask, the window says “Question 2 of 3”, and each question starts again. The address is shown in full, with the host in colour; a long address scrolls.

If the player does not answer in 60 seconds, the result is DENIED. That includes a question that the game could not show yet (the setup or a crash report was on the screen).

The player answers with the mouse. A player with only a controller cannot accept a download in this version: the question denies itself after 60 seconds, and your addon gets DENIED.

Ask only when the player needs the file. If your addon asks too frequently, Viewpoint shows fewer prompts:

  • One question of your addon waits at a time, and three in all. Another call gets NOT_SHOWN.
  • After a denial, or after a question that nobody answered, a call in the next 30 seconds gets DENIED at once.
  • After the player denies three questions, your addon gets DENIED_SESSION until the game starts again. A question that nobody answered is not one of the three.
  • The player answers with the mouse. If the game cannot show the question, you get NOT_SHOWN at once.

The addon’s Files tab shows each download: the file, the address, and the time.

What Viewpoint does not promise

Section titled “What Viewpoint does not promise”
  • Viewpoint connects only to public addresses: not to the player’s own computer or network. It looks up the host before it connects, and the connection looks it up again. The Java cache of names keeps the answer between the two for 30 seconds. If the player’s Java runs with that cache off, a server that answers a different address the second time can still reach a private address. The protection that remains is that the player sees every host.
  • The player reads the address. Two host names that look alike in the font (rn and m) are for the player to tell apart.
  • A network that only has IPv6, and translates the names of IPv4 hosts (NAT64), cannot download: Viewpoint cannot tell which address such a name leads to. The status is FAILED, and the reason says so. Few player computers are on such a network.
  • Viewpoint does not check what the file is. It keeps the file under the rules of AddonFiles, and never loads code from it.
